THE BASICS

Getting started

What is InfoMancer?

InfoMancer is a local-first catalog and management layer for movie and TV files you already own and store. It helps you browse the library, match titles to metadata, inspect media details, find gaps and duplicates, organize titles, and preview safer file changes without replacing your media server.

Does InfoMancer stream or play my media?

No. InfoMancer catalogs, audits, and organizes media. Plex, Jellyfin, Emby, or another playback system remains responsible for streaming and playback.

Does InfoMancer upload my library somewhere?

Your InfoMancer catalog stays with your installation. Matching and metadata features necessarily send title searches or provider IDs to the metadata service being queried, and IMDb dataset updates download public dataset files before retaining only records relevant to your library. This alpha does not include general product-usage telemetry.

What happens during the Setup Assistant?

The Setup Assistant walks a Librarian through time zone, TheTVDB credentials, media sources, and the first scan. Nothing is renamed, moved, or deleted while you complete setup.

Can I replay the walkthrough or setup later?

Yes. Use Take the Tour from your Profile menu to replay the interface tour. Librarians can also reopen the Setup Assistant from Help, Settings, or Profile without automatically changing existing media.

WHERE IT RUNS

Desktop and server installations

What is the difference between Standalone Desktop and a server installation?

Standalone Desktop launches an InfoMancer core on the local computer and stores its application data locally. A server installation runs the InfoMancer core on another machine and is normally used through a browser or a desktop client connected to that server.

Can the Windows desktop app connect to an existing InfoMancer server?

Yes. The desktop launcher can either start its bundled local core or connect to an existing InfoMancer server. When using a remote server during the alpha series, keeping the desktop and server on the same release line is the safest choice while formal cross-version compatibility rules continue to mature.

Does connecting the desktop app to a server give that server control of my PC?

No. After the Tauri launcher opens the local or remote InfoMancer web application, that web content is not granted broad native shell or updater commands. Native capabilities remain intentionally narrow.

Will a remote desktop client automatically understand the server's file paths?

No. A path that exists on the server does not automatically exist on the desktop computer. Native file actions should only be available when the local machine can independently resolve and access the same file or network location.

What happens to my local data during a desktop update or uninstall?

Updater-driven replacement preserves InfoMancer application data. A normal interactive uninstall is designed to remove InfoMancer-owned local state and, when a local catalog exists, offers a final chance to save a verified recovery package outside the application-data folder before removal.

ON DISK

Sources and scans

Source management and scans are available to Librarians.

What is a source?

A source is a folder containing Movies or TV Shows that the InfoMancer core can access. Movie sources may contain individual files, title folders, or alphabet and number buckets. TV sources normally contain series folders, season folders, and episode files.

What does a scan change?

A scan reads supported video files and updates the catalog. Scanning by itself does not rename, move, or delete media. When a source suddenly disappears or appears unexpectedly empty, InfoMancer is designed to preserve existing catalog data instead of assuming your library was deleted.

When should I rescan?

Scan after adding, removing, renaming, or moving media outside InfoMancer. Use Scan all sources for a broad refresh, or scan a specific source or series when you know where the change occurred.

Can Windows Desktop use mapped drives and network shares?

Yes. The Windows native build discovers accessible logical drives, including mapped drive letters. Configured locations can remain visible even while temporarily unavailable, but InfoMancer will not browse or scan them until Windows can access them again.

What about NFS, SMB, NAS, or other network storage on a server?

Mount the share on the machine running the InfoMancer core and make that mounted path available to InfoMancer. Docker deployments must also map the host path into the container. InfoMancer can use network storage, but it cannot bypass operating-system permissions, missing mounts, or unavailable network credentials.

Why can’t InfoMancer browse a folder I know exists?

The important question is whether the machine running the InfoMancer core can access it. For Desktop Standalone, that means the local Windows account. For a server install, that means the server process or container. A folder visible only on a different computer is not automatically visible to InfoMancer.

What does Windows error 1272 mean when opening a share?

Windows can return WinError 1272 when its security policy blocks unauthenticated guest access to a network share. InfoMancer now avoids crashing simply because that drive exists, but Windows still has to establish permitted access before the share can be browsed or scanned.

IDENTITY

Matching and metadata

What does matching do?

Matching connects a local title to an authoritative movie or series record. InfoMancer stores the provider identity and uses it for artwork, episode information, credits, links, ratings, and naming suggestions.

Will InfoMancer automatically apply a suggested match?

No. Automatic movie and TV suggestions still require review before they are applied. This is true for individual matching and Bulk Match workflows.

How does Bulk Match work?

Bulk Match analyzes the review queue and proposes likely identities for many titles at once. Review the proposed rows, leave questionable or unresolved items alone, select the matches you trust, and apply only those selected items. Unresolved work remains available for later review instead of being silently discarded.

What if the suggested match is wrong?

Choose Fix Match or Change Match, search again, or enter a supported provider ID or link directly. Manual review always wins over a suggestion.

What does TheTVDB provide?

TheTVDB is InfoMancer's primary matching provider for movie, series, season, and episode identity data. It supplies the information used for title matching, episode expectations, artwork, and provider-aware naming workflows.

What does IMDb provide?

InfoMancer uses selected information from IMDb's non-commercial datasets for matched titles, including data such as IMDb identifiers, ratings, genres, and credits when available. Dataset updates retain records connected to your library rather than building a complete local copy of IMDb.

Why is artwork, a rating, or cast information missing?

The title may be unmatched, may not have the expected provider identifier, or may need a metadata refresh. Metadata maintenance can refresh stale records and retry failures without discarding good metadata that is already stored.

What is the difference between scanning and refreshing metadata?

Scanning checks your media files and filesystem. Metadata refreshes query external title information such as identities, artwork, ratings, genres, and people. Neither operation renames files by itself.

UNDER THE HOOD

Media inspection and FFprobe

What is Media Inspection?

Media Inspection reads technical information from a media file, such as container, runtime, video and audio codecs, resolution, bitrate, HDR or SDR details, and stream information. Inspection is read-only and does not modify the media file.

What is FFprobe and why does InfoMancer need it?

FFprobe is the media-inspection component from the FFmpeg project. InfoMancer uses it to read technical stream and container information without transcoding the file.

Do I need to install FFprobe myself?

Supported native desktop builds include a verified FFprobe binary and run a packaged self-check. Source and server installations can use FFprobe from the system PATH or an explicit INFOMANCER_FFPROBE path.

Why did Media Inspection fail?

A failure does not automatically mean FFprobe is broken. The media file may be offline, unreadable, permission-blocked, damaged, malformed, or unavailable through a disconnected source. Read the specific failure message before changing the FFprobe installation.

Why is runtime, resolution, or HDR information missing?

The file may not have been inspected yet or its previous inspection may have failed. A Librarian can run Media Inspection from System Settings or from supported title and file actions.

TV SHOWS

Episodes and known gaps

How are missing episodes calculated?

After a series is matched, InfoMancer compares the expected aired episodes from the provider with season and episode numbers parsed from your local video files. Future episodes and specials are handled separately from ordinary aired-season gaps.

Why does a show report missing episodes that I actually have?

The filename may not contain a recognizable season and episode code, the series may be matched incorrectly, a multi-episode file may need a clearer range, or the provider's episode order may differ from your files. Check the match and naming, then rescan the series.

How do I see exactly what is missing?

Open the series and choose Missing Episodes. You can review each gap and use the configured external search link. InfoMancer opens searches but does not download media itself.

Can InfoMancer understand multi-episode files?

Yes. Supported filename patterns can identify episode ranges and multiple episode coordinates so one physical file can represent more than one logical episode.

FILESYSTEM SAFETY

File changes and protection modes

Will InfoMancer rename or move files automatically?

Normal rename, season-folder, duplicate, and organization workflows require a review or preview before media files are changed. Scanning, matching, metadata refreshes, and media inspection do not rename files on their own.

What are Standard, Read-Only, and Lockdown modes?

Standard allows reviewed media changes and normal managed cleanup behavior. Read-Only blocks filesystem changes to media. Lockdown still permits reviewed media changes but disables automatic permanent deletion so cleanup remains more conservative.

What does “No changes needed” mean?

The current file or folder name already matches the proposed format, so InfoMancer has nothing to apply.

What happens if a file changes after I preview a rename?

InfoMancer revalidates important filesystem assumptions before applying changes. If the source changed, disappeared, or a destination collision appeared after the preview, the operation is designed to fail closed instead of overwriting something unexpectedly.

Can I undo a file operation?

Supported operations are recorded in Operation History and can offer Undo. Undo is not a blind reversal: InfoMancer revalidates the current files and refuses the undo if doing so would create a collision or violate the original safety boundary.

Can I restore an older filename?

When InfoMancer recorded the original imported name, use Restore Original Filenames from the relevant title or series workflow. Review the restoration preview before applying it.

Does Duplicate Review immediately delete files?

No. InfoMancer can use size, media details, and SHA-256 fingerprints to help compare duplicate candidates. Managed-trash and permanent-cleanup actions remain explicit safety-sensitive operations, and Read-Only or Lockdown mode adds further protection.

YOUR VIEW

Favorites, tags, collections, and sorting

Who can see my favorites, ratings, and personal tags?

Personal organization belongs to your account. It helps you organize the shared catalog without changing another person's personal view or any media file.

How do I organize several titles at once?

Select movies or TV series in the Library, then use the available bulk organization actions. Selection is designed to stay intact while you work so a review or apply step does not unexpectedly lose the titles you chose.

What are Collections and Libraries?

Collections group related catalog items, while custom Libraries create additional organized views of the same underlying catalog. These features organize InfoMancer's database and do not require moving the media files on disk.

Can I customize how the Library is displayed?

Yes. InfoMancer supports List and Cover views, adjustable cover density, sorting, filters, saved views, and account-specific organization. Some defaults can also be configured by a Librarian in App Settings.

ACCESS

Accounts and roles

What is the Library Card # shown during first run?

It is the one-time bootstrap token used to create the first Librarian account. Once the first Librarian is created, that bootstrap credential is invalidated. Treat it like a temporary setup secret and do not post it publicly.

What is the difference between a Member and a Librarian?

Members can browse and search the catalog and manage their own account and personal organization. Librarians can also configure sources, scan libraries, match titles, refresh metadata, approve file changes, manage users, maintain the installation, and perform recovery operations.

Where can I change my profile or password?

Open the Profile control. Profile, Password, and Sessions let you update your account and revoke other signed-in browser sessions.

What if I forget my local-account password?

If another Librarian can sign in, they can create a single-use password-reset link from user management. If every Librarian is locked out, someone with terminal access to the InfoMancer server can generate one:

docker compose exec infomancer python -m app.cli recovery-link USERNAME --base-url https://your-infomancer-address

The link expires after one hour by default, works once, and invalidates the account's existing sessions after the new password is saved. Never share a recovery link publicly.

Why was I signed out?

Your session may have expired, been revoked, or been invalidated by a password change. Sign in again. If that fails, ask a Librarian to check whether the account is active or locked.

RECOVERY & PORTABILITY

Backups, recovery packages, and exports

What is an InfoMancer recovery package?

A .infomancer-backup recovery package is a self-verified archive containing the InfoMancer database, locally managed collection artwork, and a manifest with checksums and version information. It does not contain your media files.

Are provider credentials stored in a recovery package?

No. Provider credentials and encryption secrets are intentionally excluded from recovery packages. After restoring on another installation, reconfigure provider credentials separately.

Is restoring a recovery package destructive?

Restore uses a preview and explicit confirmation. InfoMancer verifies the package before changing the live installation and creates a safety package of the current state before committing a valid restore. A failed commit is designed to roll back rather than leave a half-restored catalog.

Which export format should I choose?

CSV is usually best for spreadsheets. Open it in Excel, Numbers, LibreOffice Calc, or a data-analysis tool to sort, filter, chart, and audit your library.

JSON is usually best for backups, scripts, structured interchange, and automation. It preserves field names and structured export information cleanly.

XML is useful when another application, automation system, or archival workflow specifically accepts XML.

What information is included in a library export?

Export formats contain the same catalog snapshot, including titles, kinds, years, source and file paths, provider IDs, ratings, genres, tags, collections, custom fields, file sizes, episode numbers, and collected media details such as runtime, resolution, codecs, bitrate, container, and HDR or SDR data when available.

Is a CSV, JSON, or XML export a complete backup?

No. Library exports are portable catalog records for reference, analysis, or integration. They do not contain a complete recoverable installation. Use an InfoMancer recovery package when you need to restore the application catalog and managed artwork.

Can I move my settings between installations?

Librarians can export and review-import portable settings such as interface defaults, time zone, external-search configuration, logging, and supported safety preferences. Accounts, sessions, API credentials, encryption keys, sources, and media are deliberately excluded.

WHEN SOMETHING LOOKS WRONG

Troubleshooting

A background task seems stuck. What should I do?

Open the task widget and read its current status first. Large scans, hashes, metadata updates, and Bulk Match analysis can take time. If the status never changes, refresh the page and have a Librarian check Activity, System Settings, and the application log.

A source says offline or unavailable. Will InfoMancer delete its catalog entries?

It should not. Source guards are designed to distinguish unavailable or suspiciously empty storage from a genuine deliberate media change. Restore the mount, mapping, credentials, or network connection, then recheck the source before performing cleanup.

A mapped drive appears but will not open. What should I check?

Confirm that the same Windows account running InfoMancer can open the drive in File Explorer. Reconnect the mapping if necessary and resolve any Windows credential or guest-access policy error. InfoMancer can discover a drive without having permission to read it.

Media Inspection failed. Should I reinstall FFprobe?

Not automatically. First check whether the file exists, the source is online, permissions allow reading it, and the error points to the media file rather than the FFprobe executable. Native desktop builds already self-check the bundled FFprobe during packaging.

Why does a recent interface change not appear?

Your browser may still have an older stylesheet or script cached. Perform a forced refresh or open a fresh private window before reporting the issue.

What information is useful when reporting a problem?

Include the InfoMancer version, whether you are using Standalone Desktop or a server, the operating system, the page or workflow involved, what you clicked, what you expected, the exact plain-language error, and a screenshot when helpful. For storage problems, also say whether the path is local, mapped, SMB, NFS, or another network mount.

What should I never include in a bug report?

Do not post passwords, API keys, subscriber PINs, session tokens, Library Card bootstrap tokens, recovery links, tunnel credentials, or other secrets. Paths and logs can also reveal usernames or network names, so review them before sharing publicly.

Where can a Librarian find logs, Activity, and catalog exports?

Use Activity for user-facing background and operation history. In App Settings → System, Librarians can inspect system status, media-inspection failures, logs, backups, and library-data export tools.
