# InfoMancer 0.8 qualification matrix

This is the repeatable qualification plan behind the 0.8 release gate. Record results for a
specific commit, operating system, filesystem/share type, and deployment type. A test is not
considered passed because a similar unit test exists; the manual matrices intentionally exercise
real storage, browser, and failure behavior.

## Filesystem torture matrix

Run destructive cases only against disposable test media. Never point this matrix at a real
library without a verified backup.

| Case | Setup | Expected result |
| --- | --- | --- |
| Destination collision | Create the proposed destination before apply | Apply refuses before overwriting anything; source remains intact; event explains collision |
| Source disappears | Preview an operation, then remove/unmount the source | Apply refuses cleanly; catalog is not rewritten as if the move succeeded |
| NAS disconnect | Preview on NFS/SMB/UNC, disconnect before commit | Operation fails closed; no fallback path is used; retry works after reconnect |
| Permission loss | Preview while writable, remove write permission before commit | Operation fails with actionable permission error; source remains authoritative |
| Permission loss mid-batch | Make first item writable and later item fail | Completed work is recorded; rollback/Undo state is accurate; no item is silently skipped |
| Symlink in source tree | Point a symlink outside the configured root | Scan/operation does not follow it into untrusted storage |
| Symlink destination trick | Replace a reviewed parent/destination with a symlink before apply | Revalidation refuses the operation |
| Case-only rename | `example.mkv` -> `Example.mkv` | Works on supported case-insensitive platforms or is refused with a safe explanation; never loses the file |
| Windows reserved name | Attempt CON/PRN/AUX/NUL/COM1/LPT1 and trailing-dot/space outputs | Preview refuses an invalid Windows target before filesystem mutation |
| Very long path | Exercise near and beyond supported path limits | Either succeeds on supported configuration or fails before partial mutation with a useful error |
| Unicode/path punctuation | Spaces, apostrophes, emoji, combining characters, non-Latin text | Round-trips without corruption or path truncation |
| Concurrent scan | Start scan while a reviewed filesystem action applies | Catalog converges to real final paths; no duplicate/phantom rows remain |
| Concurrent duplicate action | Trigger two actions against same candidate | Only one can commit; the other fails closed after revalidation |
| Undo after drift | Change/move target externally after operation | Guarded Undo refuses rather than guessing |
| Managed Trash restore collision | Recreate original destination before restore | Restore refuses overwrite and keeps trash entry recoverable |
| Read-Only mode | Attempt every media-mutating action | No media mutation occurs; scan/analysis/metadata remain available |
| Lockdown mode | Exercise irreversible/permanent cleanup paths | Stronger confirmation/retention policy remains enforced |

For each failure, capture the Event Log entry and verify that paths/tokens/secrets are not exposed
beyond what a Librarian reasonably needs to diagnose the storage problem.

## Data-durability torture matrix

Use disposable application-data directories. Keep the pre-test `.infomancer-backup` outside the
directory being faulted.

| Case | Fault | Expected result |
| --- | --- | --- |
| WAL restart | Kill process after committed WAL writes but before clean shutdown | SQLite opens cleanly and committed rows survive |
| Kill during scan write | Terminate process during a large scan transaction | Database passes integrity check; next scan converges |
| Kill during metadata update | Terminate during provider persistence | Database remains valid; incomplete work can retry |
| Corrupt backup copy | Flip bytes/truncate a copied `.db` | Validation rejects it before replacing live DB |
| Corrupt recovery archive | Flip database/artwork bytes in `.infomancer-backup` | SHA-256 verification rejects it before safety backup/live mutation |
| Disk full during DB backup | Inject ENOSPC while writing staged backup | Live DB remains untouched; partial backup is not advertised as valid |
| Disk full during recovery staging | Inject ENOSPC before commit | Live DB/artwork remain untouched |
| Failure during recovery commit | Fail after artwork swap or database swap | Automatic rollback restores both live components; portable safety package remains |
| Interrupt recovery after safety package | Terminate before commit begins | Existing installation remains usable; staged upload can be discarded |
| Interrupt recovery during commit | Fault-injection/subprocess kill at each commit boundary | Recovery procedure or documented manual safety-package recovery returns installation to a coherent state |
| Old supported schema | Restore each supported historical DB/package | Migration succeeds exactly once and preserves catalog/user state |
| Unsupported future schema | Attempt restore from newer unsupported format/schema | Restore refuses with clear version guidance |
| Backup interruption | Kill during portable package creation | Temporary file is not mistaken for a valid package; next create succeeds |
| Artwork failure | Make collection-art destination unwritable | Restore rolls database/artwork back together |
| Provider-secret sentinel | Put known bytes in provider-secret store, restore package | Sentinel is byte-identical afterward; package never supplies provider secrets |

After every case run `PRAGMA integrity_check`, exercise sign-in, open Library/Review, and create a new
backup. A durability test is not complete if the database merely opens but core state is missing.

## Large-library benchmark matrix

Use `scripts/benchmark_library.py` to establish repeatable synthetic baselines. Record at least
three runs per scale and use the median.

| Scale | Required measurements |
| --- | --- |
| ~1,000 files | initial scan, incremental scan, search, inspector/season aggregation, Review queries, fingerprint queue/hash pass, DB backup, portable recovery package |
| ~10,000 files | same |
| ~50,000 files | same |
| ~100,000 files | same |

Also record peak resident memory where practical, data-directory size, storage type, and whether the
library is local or network-backed. For NAS qualification include latency and disconnect/reconnect
behavior separately from raw throughput.

## Accessibility and responsive UI matrix

Run the same core workflow through Dashboard, Library list/grid, Inspector, title detail, Review,
Sources, Settings/Recovery, dialogs, contextual menus, and task/notification surfaces.

### Keyboard-only

- Tab/Shift+Tab order follows visual/logical order and never traps focus.
- All menus, accordions, dialogs, season controls, inspector controls, forms, and destructive
  confirmations are operable without a pointer.
- Escape closes transient surfaces where expected without losing unrelated work.
- Focus returns to the invoking control after a dialog/drawer closes.
- Visible focus is never hidden by sticky headers or clipped containers.

### Screen reader semantics

Test at least NVDA + Firefox/Chrome on Windows for 0.8. Add VoiceOver/Safari before macOS is claimed
as fully qualified UI support.

- Page title and major landmarks are understandable.
- Form controls have useful accessible names and error messages.
- Dialogs announce title/purpose and do not expose background controls as active.
- Dynamic Inspector/AJAX season loading communicates state without excessive announcements.
- Tables/lists communicate row purpose and selection state.
- Icon-only controls have names that describe the action, not the glyph.

### Zoom, motion, touch, and viewport

- 200% browser zoom at 1280×720 equivalent: no page-level horizontal scrollbar and no inaccessible
  action hidden outside the viewport.
- `prefers-reduced-motion: reduce`: no required information depends on animation; nonessential
  transitions stop.
- Touch targets are comfortably usable on phone/tablet; hover-only information has a focus/tap path.
- Test phone portrait/landscape, tablet, 1366×768 laptop, 1920×1080, 2560×1440/4K, and ultrawide.
- Long title names, long provider IDs, long file paths, many genres, many credits, and localized-length
  text wrap or truncate intentionally rather than expanding the page.
- The technical metadata rail wraps rather than creating page-level horizontal scrolling.
- Expanded TV seasons remain contained within the On Disk panel.
- The Inspector TV Media section expands seasons lazily and remains usable with dozens of episodes.

## Release-readiness manual review

Before promotion, attach evidence or links for:

- published privacy statement;
- selected project license;
- third-party notices/dependency licenses;
- FFmpeg/FFprobe build and redistribution review;
- TheTVDB/IMDb/artwork/search-provider terms and attribution review;
- exact supported OS/architecture/deployment versions;
- signed Windows installer and signed updater test;
- SHA-256 checksums and retained provenance;
- clean install -> use -> portable backup -> uninstall -> reinstall -> restore exercise;
- rollback procedure and emergency security-release drill.
