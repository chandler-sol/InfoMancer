# InfoMancer 0.8.1-alpha.1

InfoMancer 0.8.1-alpha.1 is a cleanup and hardening pass on the 0.8 alpha line, built from the `release/0.8.1-alpha.1` branch. It also carries a small set of release-blocking desktop and review-workflow fixes found during packaged-build testing.

## Security hardening

- The middleware Content-Security-Policy now mirrors the per-request template nonce, so template-rendered pages are strict at both the header and meta layer instead of relying on a permissive `'unsafe-inline'` fallback. Non-template responses keep the legacy fallback.
- Added `object-src 'none'` to the header-level CSP to match the meta policy.
- Multipart upload submissions now reject non-success responses instead of replacing the whole application view with an error page.

## Maintenance and reliability

- Background scheduler lifecycle migrated from deprecated FastAPI `on_event` hooks to lifespan handlers; boot-time deprecation warnings removed.
- Consolidated fragmented override stylesheets: Library selection, mobile chrome, and review queue polish were folded into their canonical owners with cascade order preserved.
- Retired `-polish` asset naming in favor of owner-named stylesheets such as `dialog-controls`, `library-controls`, `detail-page`, `library-saved-views`, `organize-bulk`, `recovery-restore`, and `onboarding-tour-mobile`.
- Improved Windows mapped-drive and network-share discovery, including NFS-backed drive letters and guarded handling for Windows path-resolution error 1272.
- Extended local-core cold-start tolerance and launcher diagnostics for slower first launches on Windows.
- Fixed source-browser navigation so Back can leave a mapped-drive root and return to the location chooser.
- Fixed a flaky CLI recovery-link test assertion.

## Movie matching

- Bulk movie analysis now exposes suggestions progressively. As each TVDB lookup is saved, the active movie row can show the suggested title, confidence, no-result state, or lookup error without waiting for the entire batch to finish.
- Progressive updates reuse the existing background-task signal and fetch only already-saved suggestion state. Matches are still review-only and are never applied automatically.

## Desktop preview packages

Native preview packages are built from the same commit as the server/source package:

- Windows x64: NSIS installer preview, `InfoMancer_0.8.1-alpha.1_x64-setup.exe`.
- macOS: DMG preview for the architecture used by the release runner. Not notarized; use the normal macOS override flow for unsigned development software.
- Linux x86-64: DEB and AppImage previews.

The native desktop shell bundles a local InfoMancer core and can also connect to a remote server. Native packages now bundle a pinned FFprobe 6.1.1 executable for technical media inspection, so a clean desktop installation no longer depends on a system FFmpeg installation or a modified `PATH`. Packaging verifies SHA-256 hashes for the downloaded archive, extracted executable, and accompanying upstream license, then executes the finished PyInstaller core with `--check-ffprobe` before native packaging is allowed to continue.

Source and server installations can continue to use a system `ffprobe` or an explicit `INFOMANCER_FFPROBE` path. Desktop packaging remains alpha-quality test software. The exact FFprobe redistribution obligations must be reviewed before a production release is published.

## Qualification notes

This build is intended for regression testing of the 0.8 cleanup and the release-blocking fixes found during packaged testing. Important checks include Library selection styling, mobile layouts, dialog chrome, review queue density, mapped network storage, progressive movie suggestions, FFprobe-backed media inspection, and upload flows. Filesystem-changing operations should continue to be tested with backups available.

## Integrity

Release assets are accompanied by SHA-256 checksums generated by the release workflow.
