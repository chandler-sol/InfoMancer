# InfoMancer 0.8.1-alpha.1

InfoMancer 0.8.1-alpha.1 is a cleanup and hardening pass on the 0.8 alpha line, including release-blocking desktop and review-workflow fixes found during packaged-build testing.

## Security hardening

- The middleware Content-Security-Policy now mirrors the per-request template nonce, so template-rendered pages are strict at both the header and meta layer instead of relying on a permissive `'unsafe-inline'` fallback. Non-template responses keep the legacy fallback.
- Added `object-src 'none'` to the header-level CSP to match the meta policy.
- Multipart upload submissions now reject non-success responses instead of replacing the whole application view with an error page.

## Maintenance and reliability

- Background scheduler lifecycle migrated from deprecated FastAPI `on_event` hooks to lifespan handlers; boot-time deprecation warnings removed.
- Consolidated fragmented override stylesheets: Library selection, mobile chrome, and review queue polish were folded into their canonical owners with cascade order preserved.
- Retired `-polish` asset naming in favor of owner-named stylesheets such as `dialog-controls`, `library-controls`, `detail-page`, `library-saved-views`, `organize-bulk`, `recovery-restore`, and `onboarding-tour-mobile`.
- Improved Windows mapped-drive and network-share discovery, including NFS-backed drive letters and guarded handling for Windows path-resolution error 1272.
- Extended local-core cold-start tolerance and launcher diagnostics for slower first launches on Windows.
- Fixed source-browser navigation so Back can leave a mapped-drive root and return to the location chooser.
- Fixed a flaky CLI recovery-link test assertion.

## Movie matching

- Bulk movie analysis now exposes suggestions progressively. As each TVDB lookup is saved, the active movie row can show the suggested title, confidence, no-result state, or lookup error without waiting for the entire batch to finish.
- Progressive updates reuse the existing background-task signal and fetch only already-saved suggestion state. Matches are still review-only and are never applied automatically.

## Install 0.8.1 alpha.1

Choose the file that matches your computer:

- **Windows 10/11 x64:** `InfoMancer-0.8.1-alpha.1-Windows-x64-Setup.exe`
- **Mac with Intel:** `InfoMancer-0.8.1-alpha.1-macOS-Intel.dmg`
- **Mac with Apple Silicon:** `InfoMancer-0.8.1-alpha.1-macOS-Apple-Silicon.dmg`
- **Debian / Ubuntu / Linux Mint x86-64:** `InfoMancer-0.8.1-alpha.1-Linux-x86_64.deb`
- **Other Linux x86-64 desktops:** `InfoMancer-0.8.1-alpha.1-Linux-x86_64.AppImage`
- **Docker / server:** `InfoMancer-0.8.1-alpha.1.zip`

Native packages offer two choices at launch:

- **Run on this computer** creates a standalone local InfoMancer installation.
- **Connect to a server** opens an InfoMancer server that is already running elsewhere.

> **Important:** In 0.8, a standalone native installation is local-only. **Run on this computer does not turn that desktop into a remotely available InfoMancer server.** Use the server deployment when multiple computers need to share one catalog.

Native packages bundle the FFprobe component used for technical media inspection. A separate system FFmpeg installation is not required for the packaged desktop app.

Windows alpha packages are not yet Authenticode-signed, and macOS alpha packages are not yet Apple-notarized. Download only from the official InfoMancer release and use `SHA256SUMS.txt` to verify a package when desired.

See **[Install InfoMancer](../INSTALLATION.md)** for the short platform-by-platform setup guide.

## Qualification notes

This build is intended for regression testing of the 0.8 cleanup and release-blocking fixes found during packaged testing. Important checks include Library selection styling, mobile layouts, dialog chrome, review queue density, mapped network storage, progressive movie suggestions, FFprobe-backed media inspection, and upload flows. Filesystem-changing operations should continue to be tested with backups available.

## Integrity

Release assets are accompanied by SHA-256 checksums generated by the release workflow.
